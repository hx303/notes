# Design Brief: 账户化个人知识库与无代码编辑系统

## 项目定义

wouldkeep 的核心不是“再做一个笔记软件”，而是让每个人都能拥有、整理并长期保存自己的知识，同时在本人明确选择后，让有价值的知识被他人发现、理解、引用和继续完善。

本阶段把现有公开知识花园扩展为双层产品：

- **私人工作层**：账户、草稿、编辑、组织、版本与权限，默认只有本人可见。
- **公共知识层**：经作者主动发布的稳定知识页面、主题、路径、关系与来源，继续由 Quartz 提供快速、可索引的阅读体验。

“知识需要分享”表示产品应持续帮助用户把知识整理到可分享的程度，但绝不等于默认公开、强迫公开或模糊隐私边界。

## Problem

不懂代码的用户即使完成注册，也不知道下一步该做什么；当前工作台只能在一个浏览器里保存一条本地草稿，无法形成属于账户的知识库，也无法可靠地跨设备继续编辑。主题、标签、关系和来源需要手工填写，按钮和术语缺少引导；用户无法预览公开效果、选择可见范围、回看版本或管理已经发布的内容。

用户真正面对的阻力是：“我有想法和资料，但不知道怎样把它们整理成可信、相互关联、可以放心分享的知识。”

## Solution

用户使用邮箱和密码创建账户后，通过一个三步首次引导建立自己的知识库。工作台首先呈现“我的知识”，用户可以快速记录，也可以从模板开始。编辑器使用普通文字和清晰的模块，不要求 Markdown 或代码知识；系统自动保存，并在适当时机建议主题、标签、关联知识和缺失来源。

每条知识始终显示当前状态：草稿成熟度、保存情况、可见范围和是否已发布。发布前，用户在预览页确认标题、摘要、来源、知识关系和公开范围；发布后得到稳定链接，并能继续修订、撤回或查看历史版本。公开知识进入 wouldkeep 的主题、搜索、路径和关系网络，但所有权和最终控制权仍属于作者。

## Primary User and Job to Be Done

### 首要用户：第一次建立知识库的普通用户

当我有一个问题、经验、读书笔记或资料链接时，我希望不用学习代码和复杂方法，就能先安全保存，再逐步整理成自己看得懂、以后找得到、也可以分享给别人的知识。

### 次要用户：持续维护知识的创作者

当知识不断增长时，我希望能批量管理、搜索、建立关系、回看版本，并清楚知道哪些内容公开、哪些内容仍然私密。

### 公共读者

当我读到别人分享的知识时，我希望能判断作者、成熟度、来源、更新时间与相关知识，并找到清晰的继续学习路径。

## Success Definition

首次用户无需外部说明即可完成以下闭环：

1. 用邮箱和密码注册并完成邮箱验证。
2. 建立一个有名称和默认隐私设置的个人知识库。
3. 创建并保存第一条云端草稿，刷新或换设备后仍可找到。
4. 使用标签、主题建议和已有知识搜索建立至少一个关系。
5. 预览并主动发布为“不公开链接”或“公开”，获得稳定地址。
6. 在“我的知识”中找到、继续编辑、撤回或查看该知识的历史。

体验目标：一名电脑小白在 10 分钟内完成第一条云端草稿，在 20 分钟内理解并完成一次安全分享；全程不需要接触 Git、Markdown、frontmatter、数据库或部署概念。

## Experience Principles

1. **先获得成果，再理解系统** —— 首屏只要求用户完成当前一步，高级结构与设置按需展开。
2. **控制权优先于增长** —— 默认私密，保存、同步、可见范围和发布结果始终明确，危险操作可撤销或需确认。
3. **帮助知识变得可信，而非替用户下结论** —— 自动分类与关联只提供带理由的建议，作者确认后才生效；来源、不确定性和成熟度诚实呈现。

## Aesthetic Direction

- **Philosophy**：延续“个人档案馆 × 公共知识网络”，工作区像安静清晰的编辑桌，而不是企业 SaaS 仪表盘。
- **Tone**：温暖、克制、可信、鼓励成长；面向小白时使用普通动词和完整提示。
- **Reference points**：Notion 的低门槛块编辑、Google Docs 的保存信心、Obsidian 的知识关系、GitBook 的发布预览，但不直接复制其视觉。
- **Anti-references**：密集管理后台、满屏统计卡片、社交信息流、强迫公开、以 AI 结果冒充事实、需要理解文件路径或 Git 的发布流程。

## Existing Patterns

- **技术栈**：Quartz 4.5.2、Preact、TypeScript、SCSS、静态生成与渐进式 SPA 导航；不引入第二套 UI 框架。
- **认证**：已有 Supabase 邮箱/密码注册、登录、退出和重置邮件入口，需要补全验证回跳、新密码设置、错误说明与路由保护。
- **工作台**：已有标题、主题、成熟度、标签、正文、前置/相关/来源字段，以及规则式自动分类；目前仅保存为单条 `localStorage` 草稿。
- **数据**：Supabase 已有 `profiles`、角色、评论和编辑日志，但尚无知识库、文档、版本、标签、关系和权限表。
- **Typography**：`Noto Serif SC` 用于品牌与关键标题，`Noto Sans SC` 用于正文和控件，`JetBrains Mono` 仅用于代码。
- **Colors**：暖纸色画布、暖墨文字、常青绿主行动、知识蓝链接、陶土色成熟度；支持独立校准的深色模式。
- **Spacing and shape**：4px 基础节奏，依赖排版、留白和细线分组；圆角与阴影克制。
- **Reusable components**：`Masthead`、`PrimaryNav`、`KnowledgeMeta`、`MaturityBadge`、`TagList`、`PrerequisiteBlock`、`RelatedKnowledge`、`RevisionHistory`、搜索与主题目录可延伸到公开侧。

## Core Content Model

### Supabase entities

| Entity                 | Essential fields                                                                                                                       | Ownership / purpose                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `profiles`             | `id`, `display_name`, `handle`, `bio`, `avatar_url`                                                                                    | 账户公开身份；`handle` 唯一且可修改规则明确               |
| `knowledge_bases`      | `id`, `owner_id`, `name`, `description`, `default_visibility`                                                                          | 一个用户先默认一个库，模型允许未来多个库                  |
| `documents`            | `id`, `knowledge_base_id`, `author_id`, `title`, `summary`, `body`, `topic_id`, `maturity`, `visibility`, `status`, `slug`, timestamps | 当前可编辑版本和发布状态                                  |
| `document_versions`    | `id`, `document_id`, `version_no`, `snapshot`, `created_by`, `created_at`                                                              | 发布、恢复和重要编辑时保存不可变快照                      |
| `tags`                 | `id`, `knowledge_base_id`, `name`, `normalized_name`                                                                                   | 库内标签规范化与去重                                      |
| `document_tags`        | `document_id`, `tag_id`                                                                                                                | 多对多标签关系                                            |
| `document_links`       | `from_document_id`, `to_document_id`, `relation_type`, `note`                                                                          | `prerequisite`、`related`、`continues` 等可解释关系       |
| `sources`              | `id`, `document_id`, `url`, `title`, `author`, `accessed_at`, `note`                                                                   | 一条知识可拥有多个结构化来源                              |
| `document_permissions` | `document_id`, `user_id`, `role`                                                                                                       | 后续协作所需的 `viewer` / `editor` 权限；首版只实现所有者 |

所有用户数据表启用 Row Level Security。浏览器只使用 Supabase anon key；任何 service-role key、GitHub token 或发布密钥只能存在于服务端环境。

### Status model

- **编辑状态**：`draft` → `ready` → `published` → `archived`。
- **可见范围**：`private`（仅本人）、`unlisted`（持链接可见且不进入搜索）、`public`（进入公开知识网络）。
- **成熟度**：`seed`、`growing`、`stable`，与发布状态分离；未成熟知识也可由作者明确分享。
- **保存状态**：正在保存、已保存、离线暂存、保存失败；不得只用颜色表达。

## Key Interactions

### 1. 注册、验证与恢复

- 用户选择“注册”后按钮立即可用；提交时禁用并显示进度。
- 成功后说明“已发送验证邮件、下一步做什么、未收到怎么办”，而不是只显示一句状态。
- 验证链接返回后创建/补全 profile，并进入 `/welcome/`。
- 重置邮件回跳时进入“设置新密码”表单；成功后清除恢复态并进入工作台。
- 错误尽量落在对应字段旁，并保留用户已填内容。

### 2. 首次建立知识库

- 第一步选择显示名称和公开主页地址；即时检查 handle 是否可用。
- 第二步命名知识库并选择默认隐私；默认“仅自己可见”。
- 第三步从模板或空白创建第一条知识；允许跳过，但工作台空状态继续给出同一主行动。

### 3. 创建与自动保存

- 点击“新建知识”后立即创建私密云端草稿并进入编辑页，避免内容写完才发现无法保存。
- 输入停止约 800–1200ms 后自动保存；离线时保存在本机队列，恢复网络后提示并同步。
- 多标签页或多设备发生版本冲突时不静默覆盖，提供“保留我的版本 / 使用云端版本 / 查看差异”。
- 清空和删除必须确认；删除进入可恢复的回收站，不立即物理删除。

### 4. 标签、分类与链接

- 标签输入优先显示已有标签和使用次数，允许创建新标签并自动合并大小写、全半角和同义写法。
- 自动分类先使用可解释规则或服务端模型生成候选；展示“建议：物理与光学，因为出现 RCWA、波长”，用户确认后才修改。
- 添加前置/相关知识时搜索本人库内标题和摘要，选中后显示关系方向；不要求复制 URL。
- 来源可添加多条，URL 失败不丢失输入，并允许标记“个人经验/暂无外部来源”。

### 5. 预览、发布与分享

- “预览与分享”打开与公开页面一致的预览，同时显示检查清单：标题、摘要、来源、可见范围、许可和稳定地址。
- 首次默认 `private`，用户明确改为 `unlisted` 或 `public` 后才能发布。
- `public` 内容进入主题、搜索和关系网络；`unlisted` 不进入列表、站点地图和搜索索引。
- 发布完成后提供“查看公开页面、复制链接、继续编辑”；再次发布生成版本记录，不改变稳定 URL。
- 撤回后公开地址显示适当状态或 404，原内容仍在私人工作区。

## Technical Boundary and Publishing Strategy

- Supabase Auth + Postgres 负责身份、私有数据、RLS、版本和实时保存。
- 工作区是渐进增强的动态应用界面，可沿用 Quartz/Preact 组件，但不能把账户数据烘焙进公共静态产物。
- 公开阅读继续使用 Quartz。第一版发布由安全的服务端函数读取已授权文档，生成受控 Markdown/frontmatter 或发布快照并触发构建；密钥不下发到浏览器。
- 发布任务必须幂等、可重试、有状态记录；构建失败不能改变文档的最后成功公开版本。
- 自动分类第一版采用本地可解释规则 + 人工确认；若后续引入 AI，只在服务端调用，并提供关闭选项和数据说明。

## Responsive Behavior

- **320–799px**：单列；工作台主导航折叠；编辑器工具靠近当前内容或使用底部操作栏；发布设置为全屏步骤页。输入时不被固定控件遮挡。
- **800–1199px**：知识列表与编辑区一次只显示一个主任务；辅助面板使用抽屉，不压缩正文。
- **1200px+**：工作台可使用左侧库导航 + 中央内容 + 可折叠右侧属性/关系面板，但主编辑列保持适宜阅读宽度。
- 所有宽度支持 200% 缩放、长中文/英文标题、软键盘和安全区域；常用触控目标至少 44px。

## Accessibility Requirements

- 目标为 WCAG 2.2 AA；正文与控件文字对比至少 4.5:1，大文字至少 3:1。
- 全流程可只用键盘完成；组合框、标签移除、对话框、抽屉和步骤器具有正确名称、角色、状态和焦点管理。
- 自动保存、离线、冲突、发布完成和错误通过适度的 `aria-live` 反馈；避免每次击键都朗读。
- 字段错误与说明通过 `aria-describedby` 关联；提交失败后焦点移到错误摘要，仍保留输入。
- 不依赖颜色、图标、hover 或动画表达状态；支持 `prefers-reduced-motion`。
- 密码支持粘贴、密码管理器和显示/隐藏，不设置阻碍安全长密码的不合理上限。

## Security, Privacy, and Resilience Requirements

- 每张账户数据表必须有明确 RLS 测试：所有者可读写，他人不可读私密数据，匿名用户仅可读成功发布的公开快照。
- 默认私密；公开与持链接可见需要明确动作和清晰说明。用户可以导出自己的全部知识并删除账户。
- 服务器校验 slug、URL、长度、内容类型和权限；前端校验只用于体验，不能代替服务端授权。
- 防止 XSS、恶意链接、重复提交、越权 ID 访问和公开索引泄露；富文本内容经过允许列表清理。
- 本地离线草稿不保存访问令牌；退出公共电脑时说明并清理敏感缓存。

## Measurement Plan

仅收集隐私友好的产品事件，不记录正文、标签、搜索原文或用户密码：

- 注册开始/成功/验证完成/失败类型。
- 首个知识库建立、首条云端草稿保存、首次添加标签/关系/来源。
- 预览开始、发布成功/失败、可见范围分布。
- 保存失败、冲突、离线恢复与关键流程放弃点。

核心指标是“首条可靠云端草稿”和“首次知情分享”的完成率，而不是注册数或公开数量。

## Release Phases

1. **A0 数据与安全地基**：新表、RLS、迁移、类型、测试和发布边界验证。
2. **A1 账户闭环**：邮箱验证、新密码、导航入口、路由保护与首次引导骨架。
3. **A2 我的知识**：云端多草稿、列表、搜索/筛选、自动保存和恢复。
4. **A3 无代码编辑器**：模板、模块、来源、版本、离线和冲突处理。
5. **A4 知识组织**：标签系统、分类建议、知识链接与关系可视化入口。
6. **A5 发布与分享**：预览、可见范围、稳定 URL、公开主页、撤回和构建状态。
7. **A6 小白验收与加固**：首次使用测试、无障碍、移动端、安全、性能和发布演练。

每个阶段都必须可独立演示并通过验收；A0–A2 完成后，用户已经拥有一个可靠的私人知识库，不必等待公开发布系统完成。

## Out of Scope

- 首版不实现多人实时协同编辑、团队计费、评论式审批和复杂组织权限。
- 首版不承诺任意富文本排版、第三方插件市场或桌面/移动原生应用。
- 首版不自动把用户内容设为公开，也不自动生成未经作者确认的事实性正文。
- 首版不做社交关注流、点赞排名、推荐成瘾机制或广告画像。
- 首版不要求支持多个知识库 UI，但数据库保留未来扩展能力。
- 现有公开内容的大规模归属迁移、社区治理和商业套餐另立项目。

## Acceptance Gate

只有在以下条件同时满足后，才能把账户工作区称为可用版本：

- 新用户可完整注册、验证、恢复密码并安全退出。
- 未登录用户无法访问私人工作区或通过 API 读取私人文档。
- 至少可创建、查找、编辑和删除恢复多条云端草稿。
- 刷新、断网恢复和第二设备登录不会无提示丢失内容。
- 标签、分类建议和知识链接不要求用户输入内部 URL 或代码。
- 用户能预览并明确选择 `private`、`unlisted` 或 `public`，且三种范围实际行为一致。
- 关键路径通过键盘、屏幕阅读器基础检查、320px 窄屏和 200% 缩放验收。
