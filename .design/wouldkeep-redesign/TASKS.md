## Delivery Rules

- 每个任务都是一个可构建、可查看、可验证的纵向切片；结构、样式、交互和必要测试在同一个任务内完成。
- 每完成一个任务，运行相关单元测试、`npm run check`、一次生产构建和受影响页面的键盘/移动端冒烟测试。
- 新组件使用 PascalCase `.tsx`，配套样式延续 Quartz 的 `quartz/components/styles/*.scss`，交互脚本使用 `*.inline.ts`。
- 新 UI 必须使用 `quartz/styles/tokens.scss`，不得新增无语义的硬编码颜色、间距、阴影、动效或 z-index。
- 第一项任务内安装并锁定现有项目依赖；不把“安装依赖”单独视为交付成果。
- URL 迁移、内容移动和批量 frontmatter 修改前必须保留清单，并以单跳重定向覆盖率作为完成条件。
