# Design Brief: wouldkeep 全面改版

## 项目定义

wouldkeep 是一套关于个人知识主权与公共知识分享的理念、方法和可复用知识库模板；“夔嵬的知识库”是这套方法的第一个公开示范实例。

- **主品牌**：wouldkeep
- **示范实例**：夔嵬的知识库
- **建议品牌署名**：`wouldkeep / 夔嵬`
- **品牌主张**：拥有你的知识，也让知识照见他人
- **产品边界**：公开知识花园与可复用模板，不是多人知识库 SaaS

## Problem

个人知识往往散落在私有笔记、收藏夹和平台账户中：拥有者难以长期维护，读者也难以判断一条知识从何而来、成熟到什么程度、应当从哪里继续学习。现有 wouldkeep 已经公开了大量真实内容，但首页、目录、文章工具和图谱彼此争夺注意力；重复分类、过期统计和不稳定的内容路径又削弱了探索与信任。

用户真正面对的摩擦是：他们既需要一个属于自己的知识空间，也需要一种负责任地将知识分享出去的方式；来到公开知识库的人则需要快速找到有价值、可理解、可追溯、可继续探索的知识，而不是先学会操作网站。

## Solution

把 wouldkeep 改造成“个人档案馆 × 公共知识网络”：首页先帮助访客在 30 秒内理解理念，并通过知识地图、主题和学习路径进入内容；文章页成为带有成熟度、更新时间、前置知识、引用和修订线索的知识记录；搜索、目录和阅读工具始终可达但不干扰阅读；全局图谱升级为独立的“知识地图”探索空间。

体验同时示范一套可复用的公开发布方法：作者主动选择公开内容、明确知识成熟度与来源、保留旧链接并提供修订痕迹；读者可以继续阅读、引用、分享、讨论和纠错，也可以复制模板建立自己的知识库。

## Primary Users and Jobs to Be Done

### 1. 求知型访客（首要）

当我带着一个问题或模糊兴趣来到站点时，我希望用搜索、目录、地图或学习路径在两次操作内抵达有价值的内容，并能判断它是否可信、是否适合我、下一步应读什么。

### 2. 潜在知识库建立者（次要）

当我看到一个持续生长的公开知识库时，我希望理解 wouldkeep 的方法，知道如何划分公开与私有边界，并获得可复用模板来建立自己的知识库。

### 3. 回访读者与贡献者

当我重访某个主题时，我希望看到它最近如何生长，并能通过评论、纠错建议、引用或分享参与知识的完善，而无需加入一个社交网络。

## Success Definition

- 新访客能在 30 秒内说清楚 wouldkeep 的核心理念。
- 从首页到任一高价值主题或学习路径不超过两次主要操作。
- 搜索、知识目录和知识地图都能独立完成内容发现，不形成死胡同。
- 文章的前置知识、相关笔记和反向链接能形成清晰的继续阅读路径。
- “建立你的知识库”模板入口清晰可见并产生实际使用。
- 评论、纠错、引用与分享都有可理解的反馈状态。
- 移动端、键盘操作、深色模式与 200% 缩放下核心任务完整可用。
- 性能、构建可靠性与已有公开 URL 稳定性不低于改版前。

## Experience Principles

1. **知识价值优先于站点说明** —— 先让用户抵达内容，再用适量上下文解释体系；每个页面都应提供清晰的下一步。
2. **诚实生长优先于虚假完备** —— 公开成熟度、更新时间、来源和修订状态，让不完整成为可理解的知识阶段，而不是质量缺陷。
3. **个人主权与公共参与并存** —— 作者主动决定公开边界，读者可以纠错、讨论、引用和复用，但产品不通过关注流、私信或排名制造社交压力。

## Aesthetic Direction

- **Philosophy**：个人档案馆 × 公共知识网络
- **Tone**：温暖、安静、可信、求知、持续生长；具有人的痕迹，但不怀旧造作
- **Reference points**：公共图书馆目录卡、档案索引与修订记录的秩序感；Wikipedia 的可追溯性；Are.na 的主题探索；Obsidian/Quartz 数字花园的链接关系。只借鉴体验特征，不进行视觉复刻。
- **Visual language**：从偏黄的“文学花园”转向更克制的暖中性色；衬线字体只承担品牌与关键标题，无衬线承担导航、元数据和工具；用目录编号、版本、引用、路径和连线表达知识结构；首页知识地图可以更有张力，文章页保持安静。
- **Anti-references**：通用博客模板、Notion 仪表盘、赛博朋克关系图、满屏玻璃卡片、过度 emoji、装饰性复古纸张、算法信息流和企业 SaaS 控制台。

## Existing Patterns

项目当前使用 Quartz 4.5.2，基于 Preact、TypeScript 与 SCSS，以静态生成和渐进式客户端交互为基础。没有 Tailwind、Material UI、Chakra、shadcn、Storybook 或独立组件库，因此改版应扩展 Quartz 现有组件体系并逐步建立令牌，而不是引入第二套 UI 架构。

- **Typography**：本地字体；标题 `Noto Serif SC`，正文 `Noto Sans SC`，代码 `JetBrains Mono`。继续使用这套中英文字体基础，但收紧衬线字体的使用范围。
- **Colors**：主题配置提供 `light/lightgray/gray/darkgray/dark/secondary/tertiary/highlight/textHighlight` 两套明暗变量。现有浅色以 `#fdf6ee` 为纸色、棕色和绿色为强调；深色已有对应变量。后续应扩展为语义令牌并降低黄调。
- **Spacing and layout**：SCSS 断点为 800px 与 1200px；基础布局是 320px 左右侧栏加中间内容区，正文自定义宽度约 780–840px。
- **Existing components**：PageTitle、Search、Explorer、Darkmode、FontSize、ReaderMode、Breadcrumbs、ArticleTitle、ContentMeta、TagList、TableOfContents、Backlinks、Graph、RecentNotes、Footer、BackToTop、SupabaseComments。
- **Existing capabilities**：SPA 导航、链接预览、全文搜索、目录树、主题切换、阅读模式、目录、反向链接、局部/全局图谱、引用处理、RSS、站点地图、别名重定向与评论。
- **Content source**：真实 Markdown 知识内容是界面主体。首页数量、最近更新和主题规模必须从内容索引生成，不再使用手工占位或过期统计。

## Current Experience Risks to Resolve

- 页面骨架缺少明确的 `<main>` 地标和跳过导航入口。
- 搜索、主题等图标按钮的可访问名称和焦点处理不一致，部分标签落在 SVG 而非按钮上。
- 小型工具按钮和部分目录控件不足以形成稳定的触控目标。
- 缺少统一 `:focus-visible`，搜索样式还移除了默认轮廓。
- 多处使用 `transition: all`，且没有完整的 `prefers-reduced-motion` 降级。
- 评论失败可能静默发生，异步反馈缺少稳定的 `aria-live` 通知。
- 全局图谱长期占据文章右栏，干扰阅读且探索能力不足。
- 首页统计存在过期风险，内容分类存在重复命名，长期 URL 易受文件夹结构影响。

## Information and Content Model

每篇公开知识记录至少需要支持以下语义；可以从 frontmatter、Git 历史和内容关系组合生成，避免作者重复填写：

- 永久 slug 与历史 aliases
- 知识成熟度：萌芽 / 整理中 / 相对完整
- 创建与最近修订时间
- 摘要与所属主题
- 前置知识、相关笔记与反向链接
- 引用来源与建议引用方式
- 公开范围、复用许可与必要的内容提示
- 可选修订说明或版本记录

发布是主动行为，不默认公开整个私人仓库。敏感信息、私人内容、本地路径、未获授权材料和无法确认许可的数据不得进入公开构建。

## Key Interactions

### 首页探索

访客先看到品牌定义与两个行动入口；向下浏览时依次获得知识地图预览、主题/学习路径和最近生长。所有统计均来自构建数据。选择主题后进入主题导览；选择路径后看到目标、前置条件、步骤和进度语义，而不是落到无解释的文件夹列表。

### 搜索

点击按钮或使用快捷键打开搜索；输入后立即展示标题、摘要、主题、成熟度和匹配上下文。键盘可完整移动、预览、选择和关闭。无结果时提供检查关键词、浏览邻近主题和打开目录的出口；加载或错误状态被屏幕阅读器感知。

### 阅读一篇知识记录

文章顶部先回答“这是什么、成熟到什么程度、何时更新、需要先知道什么”；正文保持低干扰。滚动时目录提示当前位置，阅读工具仍可达。文章尾部按“继续学习—来源与修订—参与完善”排序，呈现相关笔记、反向链接、引用/分享、纠错与评论。

### 知识地图

地图默认按主题形成可解释的群组。选择节点后聚焦相邻知识并显示文本详情；筛选器可以限制主题和成熟度。视觉图谱必须提供等价的列表/路径视图，移动端优先使用分组列表和局部关系，避免强行缩小完整画布。

### 参与与反馈

评论和纠错操作必须明确区分目的。提交时显示进行中状态，成功后确认结果，失败时保留输入并说明恢复方式。复制引用、复制链接和系统分享均提供非阻塞反馈。站点不要求关注关系、私信或账户社交化。

### 建立自己的知识库

次级 CTA 进入方法与模板页面：先解释个人知识主权和主动发布边界，再展示最低可行步骤、示例内容结构、部署方式和可复用模板。它应让读者能够行动，而不仅是品牌宣言。

## Responsive Behavior

- **Narrow / mobile（<800px）**：单列阅读；Masthead 简化；目录和阅读工具进入底部或顶部紧凑工具入口；知识目录使用抽屉；文章元数据换行但不隐藏成熟度和更新时间；知识地图默认采用列表/局部关系视图；主要触控目标至少 44×44px。
- **Medium / tablet（800–1200px）**：保留一个主要侧栏或上下文栏，另一个区域按需折叠；文章仍保持舒适行长；搜索覆盖层与地图详情不依赖 hover。
- **Wide / desktop（≥1200px）**：左侧承担品牌、搜索和目录；中间保持约 70–80 个中文字符以内的可读宽度；右侧只放当前任务需要的目录或文章上下文，不再固定展示全局图谱。
- **Zoom and reflow**：200% 缩放时不得依靠横向滚动完成普通阅读；代码、表格和图谱可在自身容器中滚动，并具有可理解提示。

## Accessibility Requirements

- 以 WCAG 2.2 AA 为最低基线，文本和控件对比度分别满足 4.5:1 与 3:1 要求。
- 提供可见的“跳到正文”链接、唯一 `<main>`、语义化导航与辅助区域，保持逻辑标题层级。
- 所有交互可用键盘完成；焦点顺序与视觉顺序一致；弹层打开后正确移动焦点，关闭后返回触发器。
- 所有按钮的可访问名称位于按钮本身；纯装饰图标 `aria-hidden`；不以颜色、形状或位置作为唯一信息来源。
- 使用统一且高对比的 `:focus-visible`；不得用 `outline: none` 取消焦点而不提供替代。
- 触控目标优先达到 44×44px，密集控件至少保留足够间距以避免误触。
- 搜索、评论、复制、纠错与地图筛选的加载/成功/失败状态通过适当的 `aria-live` 暴露，但避免重复播报。
- 尊重 `prefers-reduced-motion`；关闭非必要平滑滚动、位移动画、图谱持续运动和阅读进度动画。
- 深色模式、字号调整、高对比情境、屏幕阅读器和仅键盘操作均纳入验收。
- 中英文混排、长标题、长 URL、代码块、表格、公式和图像替代文本必须具备稳健的溢出与阅读策略。

## Performance and Technical Constraints

- 保持 Quartz 的静态优先架构、SPA 渐进增强和 Markdown 内容工作流。
- 不为常规 UI 引入重型组件框架；优先扩展现有 Preact 组件与 SCSS。
- 首页地图和独立图谱按需加载，避免阻塞首屏；尊重低性能设备和减少动态偏好。
- 字体继续本地托管并控制字重数量；图标使用统一 SVG 系统。
- 旧 URL 必须通过永久 slug、aliases 或重定向继续工作；搜索索引、RSS、站点地图、评论映射和图谱链接同步迁移。
- 内容重组前生成 URL 清单和重定向映射；构建过程检查内部断链与关键外链状态。
- 匿名分析只记录页面访问、搜索使用、学习路径点击、模板 CTA 和外链失效等聚合事件；不记录身份、不做跨站广告追踪，并提供清晰隐私说明。

## Content Migration Rules

- 合并重复主题与重复文件夹命名，但先建立旧路径到新永久 slug 的映射。
- 永久 URL 不依赖 emoji、排序编号或易变化的目录名称。
- 首页数据、主题数量和最近更新由构建过程生成。
- 为高价值内容优先补齐摘要、成熟度、前置知识、相关笔记、引用和许可；其余内容允许渐进迁移。
- 迁移不得把 `private`、模板源文件、Obsidian 配置、备份或未授权材料带入公开站点。

## Measurement Plan

采用隐私友好的匿名聚合分析，验证而非操纵体验：

- 首页理念区到知识地图、主题和模板页的点击率
- 从落地到首次有效内容访问的操作数
- 搜索打开、有效查询、结果点击和无结果比例
- 学习路径开始与后续步骤访问
- 相关文章、前置知识和反向链接的继续阅读
- 引用、分享、纠错与评论的使用及失败率
- 旧 URL 命中重定向、内部断链和关键外链失效
- Core Web Vitals、构建时间、脚本体积与图谱加载成本

不得以停留时长、无限浏览或账户增长作为核心成功标准。

## Out of Scope

- 多租户 SaaS、站内创建私人知识库、云端笔记同步和完整 CMS
- 站内投稿、多作者发布工作流和公开内容审核平台
- 关注/好友、私信、个性化推荐流、排行榜、点赞经济与社交关系图
- 默认自动发布整个私人知识库
- 付费墙、广告系统、跨站追踪和用户画像
- 用 AI 自动生成或替代作者知识内容；本次只允许未来为检索与辅助整理预留接口
- 原生移动应用
- 在本阶段直接确定最终像素稿、完整设计令牌或实现代码；这些属于后续 design-flow 阶段

## Acceptance Gate for the Next Phase

后续设计令牌、信息架构和实现任务必须能逐项追溯到本简报。任何新增社交功能、账户体系、发布方式或数据收集如果超出上述边界，需要重新确认，而不能在实现阶段默认扩张。
