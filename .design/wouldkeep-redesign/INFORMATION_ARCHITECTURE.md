# Information Architecture: wouldkeep 全面改版

## Structural Decisions

- **最高频任务**：查找并阅读知识，其次是沿主题/路径继续学习，再次是理解并复用 wouldkeep 方法，最后是评论、纠错、引用和分享。
- **导航深度**：面向读者最多三层——全局入口 → 主题或路径 → 知识记录。文件系统可以更深，但不得直接暴露为主要导航。
- **80% 核心视图**：知识记录页。首页、主题页、搜索、路径和地图最终都为进入与继续阅读服务。
- **持续增长内容**：知识记录、主题关系、学习路径、最近生长、标签和修订历史。
- **相对固定内容**：wouldkeep 理念、公开边界、建库方法、模板说明、隐私与许可。
- **用户入口**：求知者从主题、搜索、路径和地图进入；建库者从“建立知识库”进入；两者共享文章、方法和公开规范，不建立不同账户区域。

## Current Structure Findings

- 当前共有 256 个 Markdown 文件，其中 200 个位于两层文件夹之下。
- `📖 课堂笔记`包含 179 篇，同时还存在另一个无 emoji 的`课堂笔记`目录；当前顶层目录把“学科主题”和“内容形式”混在一起。
- 现有主要内容规模包括：微积分下 48、微积分上 32、线性代数 26、大学物理 23、量子力学课程 22、有机化学 11、中华民族发展史 11、中国近代史 10。
- 只有 16 篇内容配置了 aliases；首页仍写“120+”，与实际 256 篇不一致。
- 目前有 20 个 `index.md`，它们是主题枢纽的可复用起点，但质量与字段并不统一。
- frontmatter 已广泛使用 `title`、`date`、`tags`、`created`、`subject`；`description`、`updated`、`prerequisites`、`status` 和 aliases 覆盖不足。
- 标签存在中英文并行、同义词、内容形式与主题混用的问题。
- Quartz 当前 canonical slug 由文件路径生成；现有 `permalink` 实际作为额外重定向地址，不会替换 canonical。目标 URL 若要与文件结构解耦，需要新增 canonical slug 能力或在迁移时移动文件并保留 aliases。

## Classification Model

新架构把一个知识记录的身份拆成五个互不替代的维度：

1. **主题 Topic**：知识“关于什么”，决定主目录和主题页归属。
2. **类型 Type**：它“以什么形式存在”，例如课程笔记、研究记录、文献解读、讲座笔记、速查或自测。
3. **成熟度 Maturity**：萌芽、整理中、相对完整。
4. **关系 Relations**：前置知识、相关知识、学习路径、引用和反向链接。
5. **来源与责任 Provenance**：作者、来源、修订时间、许可、公开边界。

文件夹不再同时承担主题、类型和 URL。Explorer 将依据元数据生成“知识目录”，而不是原样展示磁盘目录。

## Site Map

- 首页 `/`
  - 直接入口：主题、学习路径、知识地图、建立知识库
- 主题 `/topics/`
  - 主题页 `/topics/:topic-slug/`
    - 子主题锚点或筛选，不再增加 URL 层级
- 学习路径 `/paths/`
  - 路径详情 `/paths/:path-slug/`
- 知识地图 `/map/`
  - 聚焦状态通过查询参数分享，不生成独立页面
- 最近生长 `/changes/`
  - 月度归档 `/changes/:yyyy-mm/`
- 知识记录 `/notes/:canonical-slug/`
  - 内容内部锚点 `#section-slug`
- 搜索 `/search/?q=:query`
  - 桌面与移动可使用覆盖层；此 URL 提供可分享、可降级的完整结果页
- 建立你的知识库 `/build/`
  - wouldkeep 方法 `/build/method/`
  - 公开边界 `/build/publishing-boundaries/`
  - 内容模型 `/build/content-model/`
  - 模板与部署 `/build/template/`
- 关于 `/about/`
  - wouldkeep 理念 `/about/philosophy/`
  - 夔嵬与这座知识库 `/about/kuiwei/`
- 辅助页面
  - 标签 `/tags/` 与 `/tags/:tag/`（保留但不进入主导航）
  - 隐私 `/privacy/`
  - 许可 `/license/`
  - RSS `/index.xml`
  - 站点地图 `/sitemap.xml`
  - 404 `/404`
- 旧路径
  - 原文件夹页与原文章 URL → 单跳 301/静态 canonical redirect → 新 canonical URL

## Initial Learning Paths

学习路径必须人工策划，有明确目标、前置知识、顺序和完成条件；不是按文件名排序的集合。

1. **理工科数学基础**：极限与微积分 → 线性代数 → 向量与场的预备知识。
2. **从物理到光学建模**：大学物理 → 电磁与光学基础 → Fresnel/TMM → RCWA。
3. **钙钛矿太阳能电池诊断**：材料与器件基础 → J-V 与光学诊断 → 反向工程 → 实验设计。
4. **量子力学概念路径**：Stern–Gerlach → 双缝 → 波粒二象性 → 光的量子性 → 应用。
5. **COMSOL 入门实践**：建模流程 → 几何 → 网格 → 结果与可视化。
6. **中国近现代与民族关系**：关键历史节点 → 多民族互动 → 近现代国家形成。

首发不要求六条路径全部达到同等深度；至少完成三条高质量路径，其余可以标记为“建设中”。

## Navigation Model

### Primary navigation

主导航最多四项，品牌字标返回首页：

1. **主题** `/topics/`
2. **学习路径** `/paths/`
3. **知识地图** `/map/`
4. **建立知识库** `/build/`

主导航不放“首页”“标签”“最近更新”或社交入口，避免与核心探索任务竞争。

### Secondary navigation

- **知识目录**：桌面左栏按主题 → 子主题组织，可切换“主题视图 / 类型视图”；显示当前位置，不显示磁盘文件夹和 emoji。
- **主题页局部导航**：概览、推荐起点、路径、全部知识；子主题作为锚点或筛选。
- **路径页局部导航**：目标、前置、步骤、延伸阅读。
- **文章右侧上下文**：桌面仅放文章目录与当前阅读上下文；全局图谱不再固定出现。
- **面包屑**：使用主主题路径，如“主题 / 物理与光学 / 电磁感应”；多主题文章只选择一个主主题用于面包屑。

### Utility navigation

- 搜索
- 深色/浅色模式
- 字号
- 阅读模式
- RSS
- 最近生长
- 关于、隐私、许可、GitHub

搜索、主题切换、字号和阅读模式始终可达，但视觉权重低于内容与主导航。

### Mobile navigation

- 顶部紧凑栏：品牌、搜索、菜单。
- 底部或贴边阅读工具：目录、字号/阅读模式、更多；只在阅读页出现。
- 菜单抽屉包含四个主导航入口、最近生长和主题目录；打开后焦点进入抽屉，关闭后返回触发器。
- 知识目录与文章目录使用不同标签，避免都叫“目录”。前者叫“知识目录”，后者叫“本文目录”。
- 不使用溢出的桌面横向导航，也不把整个三栏布局缩小到手机。

## Content Hierarchy

### 首页

1. **品牌定义与行动入口** —— 30 秒内解释“个人知识主权 × 公共知识分享”；主 CTA“探索知识地图”，次 CTA“建立你的知识库”。
2. **精选主题与学习路径** —— 让访客无需理解文件结构即可进入真实内容。
3. **知识地图预览** —— 表达跨主题关系，并链接完整地图。
4. **最近生长** —— 展示真实新增与重要修订，不显示手工篇数。
5. **方法与公共参与** —— 简述成熟度、引用、纠错和模板。

### 主题索引

1. 七个一级主题及一句话范围说明
2. 推荐起点与热门学习目标
3. 主题关系预览
4. 类型、成熟度和最近更新筛选

### 主题页

1. 主题是什么、适合谁、应从哪里开始
2. 推荐起点与相关学习路径
3. 子主题和概念关系
4. 按类型/成熟度筛选的全部知识
5. 邻近主题与跨域连接

### 学习路径详情

1. 学习目标、适合对象、前置知识和维护状态
2. 有顺序的核心步骤，每步说明“为什么在这里”
3. 可选分支、自测和延伸材料
4. 路径修订记录与相关主题

### 知识地图

1. 当前范围、筛选与文字说明
2. 可交互关系图或等价列表视图
3. 聚焦节点详情、相邻知识和进入文章的行动
4. 地图图例、数据范围和无障碍帮助

### 知识记录

1. 标题、摘要、成熟度、主主题、更新时间
2. 前置知识与本文解决的问题
3. 正文与本文目录
4. 来源、引用方式和修订信息
5. 继续阅读：相关知识、路径位置、反向链接
6. 参与：纠错、评论、分享

### 建立知识库

1. 为什么个人应拥有自己的知识，以及分享的价值
2. 最小可行知识库的建立步骤
3. 私有、待整理、公开三类边界
4. 内容模型、成熟度和引用方法
5. 模板获取与部署
6. 示例：夔嵬的知识库如何应用这套方法

### 最近生长

1. 重要修订与新增长内容
2. 按主题和变更类型筛选
3. 月度归档
4. RSS 订阅入口

## User Flows

### 通过主题找到答案

1. 用户从首页或主导航进入“主题”。
2. 选择一个一级主题，看到范围、推荐起点和学习路径。
3. 用户选择推荐知识或使用类型/成熟度筛选。
4. 到达知识记录，先判断摘要、成熟度和前置知识。
5. 阅读后沿相关知识或路径继续。

### 通过搜索解决具体问题

1. 用户在任意页面打开搜索并输入关键词。
2. 结果显示标题、摘要、主题、类型、成熟度与匹配上下文。
3. 若有精确结果，直接进入知识记录。
4. 若无结果，提供相近主题、清除筛选和知识目录入口。
5. 查询可通过 `/search/?q=` 分享或在无脚本环境打开。

### 沿学习路径系统学习

1. 用户进入学习路径索引并选择目标。
2. 路径页说明对象、前置、步骤和当前维护状态。
3. 用户进入某一步；文章显示它在路径中的位置。
4. 返回路径或进入下一步。
5. 若缺少前置知识，先进入前置内容，再返回原步骤。

### 从知识地图探索关系

1. 用户从首页 CTA 或主导航进入知识地图。
2. 选择主题/成熟度，或切换地图与列表视图。
3. 聚焦节点后看到相邻节点与关系类型。
4. 用户进入知识记录；返回时恢复地图焦点与筛选。
5. 若设备性能低或 reduced motion 开启，默认使用列表/局部关系视图。

### 建立自己的知识库

1. 用户从首页次 CTA 或主导航进入“建立知识库”。
2. 先理解 wouldkeep 原则和公开边界。
3. 查看最小步骤、内容模型与示范实例。
4. 选择获取模板或查看部署说明。
5. 模板 CTA 被匿名计数，但不要求登录或提交个人信息。

### 纠错或讨论

1. 用户在知识记录尾部选择“纠错建议”或“参与讨论”。
2. 纠错入口说明需要提供的位置、问题和建议；评论保持开放讨论语义。
3. 提交时显示进行中状态。
4. 成功时给出明确确认；失败时保留输入并说明重试方式。
5. 不把参与扩展为关注、私信或投稿系统。

### 旧链接访问

1. 用户从搜索引擎、收藏夹或外部引用打开旧 URL。
2. 静态重定向单跳到新 canonical URL。
3. 页面 canonical、RSS、搜索索引和分享链接均使用新 URL。
4. 评论通过稳定 `commentKey` 或迁移映射继续关联原讨论。
5. 无映射时进入有建议搜索和相关主题的 404，而不是空白页。

## Content Growth Plan

- **主题**：一级主题长期保持 5–7 个；新增内容优先进入现有主题，只有出现持续且独立的知识群时才新增一级主题。
- **知识记录**：使用搜索、主题和类型筛选扩展到上千篇；主题页先展示策划内容，再展示每页 24–36 条的全量列表。
- **学习路径**：人工维护并显示“建设中 / 可学习 / 待修订”的路径维护状态；不自动把标签列表伪装成路径。
- **最近生长**：按月归档，默认只展示重要修订和新增；小修正折叠，避免形成噪声流。
- **标签**：作为长尾关系层，不进入主导航；建立同义词表并逐步合并中英文重复标签。
- **知识地图**：先按当前筛选加载局部图，用户主动展开；提供列表视图，避免一次渲染全部节点。
- **成熟度迁移**：缺少状态的现有内容默认标为“萌芽”，已有 `status: complete` 映射为“相对完整”；高流量内容人工复核后再升级。
- **主题枢纽**：现有 20 个 `index.md` 经审核后转为主题、子主题或路径页；自动文件夹页只保留为迁移兼容层。

## Content Schema

| Field | Required | Purpose |
| --- | --- | --- |
| `title` | Yes | 人类可读标题 |

## URL Strategy

### Canonical patterns

- 知识记录：`/notes/:canonical-slug/`
- 主题：`/topics/:topic-slug/`
- 学习路径：`/paths/:path-slug/`
- 月度生长：`/changes/:yyyy-mm/`
- 方法页：`/build/:page-slug/`

`canonical-slug` 使用短、稳定、无 emoji、无排序编号的 kebab-case。对于中文内容，优先使用易维护的英文概念或约定俗成缩写；不强制冗长拼音。URL 一旦公开不因标题、主题或文件位置改变。

### Query parameters

- 搜索：`q`、`topic`、`type`、`maturity`
- 主题列表：`type`、`maturity`、`sort`
- 知识地图：`topic`、`maturity`、`focus`、`view=map|list`
- 最近生长：`topic`、`change=created|revised`

过滤状态应写入 URL 以便刷新、返回和分享；展示偏好如字号、主题和阅读模式保存在本地，不进入 URL。

### Redirect rules

1. 迁移前导出所有当前 public slug。
2. 每篇移动内容把所有旧 slug 写入 aliases；同一旧地址只能对应一个目标。
3. 重定向必须单跳，不允许 old → intermediate → new 链。
4. 构建时检查 canonical 冲突、遗漏旧 URL、内部断链和重定向环。
5. canonical、Open Graph、RSS、站点地图、搜索索引和复制链接统一输出目标 URL。
6. 评论使用稳定 `commentKey`，不再直接依赖可变化文件路径。
7. `/tags/*` 暂时保留；重复顶层文件夹页在内容迁移完成后重定向到对应主题页。

## Migration Sequence

1. 冻结并导出当前 URL、标题、文件路径、aliases、评论键和入链数量。
2. 建立主题/类型/成熟度同义词表与字段映射。
3. 实现 `canonicalSlug`、稳定 `commentKey` 和构建期 URL 审计。
4. 先迁移首页、七个主题页、首发学习路径和高价值/高入链文章。
5. 再批量补齐剩余内容的主主题、类型、成熟度和 aliases。
6. 合并`课堂笔记`重复目录以及空目录，但不直接删除任何公开路径。
7. 更新搜索、RSS、站点地图、图谱和内部链接使用 canonical URL。
8. 通过旧 URL 清单、关键流程、404 报告和部署预览验证后再发布。

## Out-of-Structure Decisions

- 不按课堂/科研/讲座等来源形式建立多个平行顶层站点。
- 不把标签云当作主信息架构。
- 不让知识地图成为唯一探索方式。
- 不建立用户空间、社区分区、动态流或投稿中心。
- 不在本阶段移动、重命名或批量修改文章；本文件只定义目标结构和迁移规则。
